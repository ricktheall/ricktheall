# TheAll Bible Coffee — V2

**1 Coffee. 1 Bible. 1 Day.** · หนึ่งถ้วย · หนึ่งบท · หนึ่งวันที่ถูกจัดใหม่
**66 แก้ว · 66 เล่ม · เรื่องเดียว**

V2 เปลี่ยน TheAll Bible Coffee จาก *เว็บเนื้อหาพระคัมภีร์ที่สวยงาม*
ให้เป็น *การเดินทางส่วนตัวผ่านพระคัมภีร์ ที่จำได้ว่าแต่ละคนเดินไปถึงไหนแล้ว*

ทุกหน้าจอตอบสามคำถามนี้ภายในไม่กี่วินาที

1. ตอนนี้ผมอยู่ตรงไหนของพระคัมภีร์
2. ผมเดินมาไกลแค่ไหนแล้ว
3. ต่อไปควรอ่านอะไร

---

## แก้ว 4 สถานะ

| สถานะ | เมื่อไร | หน้าตา |
|---|---|---|
| **กำลังเตรียม** `coming_soon` | ยังไม่มีบทเรียนของเล่มนี้ | แก้วเบลอ จางลง แต่ยังเห็นรหัส ชื่อไทย และจำนวนบท |
| **พร้อมอ่าน** `ready` | มีบทเรียนแล้ว แต่ยังไม่เริ่ม | แก้วคมชัด มีจุดเขียวเล็ก ๆ |
| **กำลังอ่าน** `in_progress` | เริ่มแล้วแต่ยังไม่จบ | วงแหวนทองรอบแก้ว + จำนวนบทที่อ่านแล้ว |
| **อ่านจบแล้ว** `completed` | อ่านครบทุกบท | **แก้วคว่ำลง** + เครื่องหมายถูกสีทอง + วันที่อ่านจบ |

พระคัมภีร์ทั้ง 66 เล่มปรากฏในห้องสมุดเสมอ — ไม่เคยซ่อนเล่มที่ยังไม่พร้อม
เพราะห้องสมุดต้องสื่อสารว่า *"การเดินทางทั้งหมดยังรออยู่ข้างหน้า"*

**ความพร้อมของบทเรียน** กับ **ความคืบหน้าของผู้ใช้** เป็นคนละเรื่องกันในโค้ด
เล่มหนึ่งเป็น `lessonStatus = ready` และ `userStatus = completed` พร้อมกันได้

## โครงสร้างไฟล์

```
coffee/
├── index.html      โครงหน้า + แถบบน + แถบนำทางล่าง
├── books.js        ★ ข้อมูลพระคัมภีร์ 66 เล่ม — แหล่งความจริงเดียว
├── lessons.js      ★ ทะเบียนบทเรียน: เล่มไหนพร้อม + ช่องเสียบเนื้อหาจริง
├── i18n.js         พจนานุกรมข้อความ ไทย/อังกฤษ
├── cups.js         ตัวเรนเดอร์แก้ว (รูปจริง หรือ SVG) + การคว่ำแก้ว
├── progress.js     ProgressRepository + localStorage + migration
├── app.js          เราเตอร์และหน้าจอทั้งหมด
├── styles.css      ระบบออกแบบ ดำอบอุ่น/ครีม/ทอง มือถือก่อน
├── sw.js           service worker (network-first)
└── icons/          ไอคอนแอป
```

ไม่มี build step ไม่มี framework ไม่มี dependency — เปิดไฟล์แล้วใช้ได้เลย

```bash
python3 -m http.server 8000   # แล้วเปิด http://localhost:8000/coffee/
```

## การเพิ่มบทเรียน

`lessons.js` คือ **ช่องเสียบเนื้อหา ไม่ใช่ตัวสร้างเนื้อหา**
ห้ามแต่งเนื้อหาศึกษาพระคัมภีร์ขึ้นเองเพื่อให้ห้องสมุดดูครบ

**1. เปิดเล่มให้พร้อมอ่าน**

```js
const READY_BOOKS = ['GEN', 'EPH', 'REV', 'JHN'];   // เพิ่มรหัสเล่ม
```

**2. ใส่เนื้อหาบทเรียนจริง (ถ้ามีแล้ว)**

```js
LESSON_CONTENT['GEN'] = {
  chapters: {
    1: {
      title: { th: '…', en: '…' },
      brew:  { th: '…', en: '…' },
      read:  { th: '…', en: '…' },
      live:  { th: '…', en: '…' },
    },
  },
};
```

บทที่ยังไม่มีเนื้อหาจะแสดง **จังหวะประจำวัน ชง → อ่าน → ใช้ชีวิต**
ซึ่งเชิญให้อ่านบทนั้นจากพระคัมภีร์ของผู้ใช้เอง แล้วกลับมาบันทึกความคืบหน้า
โดยไม่แต่งคำอธิบายพระคัมภีร์ขึ้นมาแทน

## การเพิ่มรูปแก้วจริง

ตอนนี้แก้วถูกวาดด้วย SVG โดยสุ่มทรง/สี/หูจับจากรหัสเล่มแบบคงที่
(แต่ละเล่มได้แก้วประจำตัวที่เหมือนเดิมทุกครั้ง) เพื่อให้ระบบทำงานได้ก่อน

เมื่อมีรูปถ่ายแก้วจริง

1. วางไฟล์ที่ `coffee/cups/<code ตัวเล็ก>.webp` เช่น `coffee/cups/gen.webp`
2. เพิ่มรหัสเล่มใน `CUP_PHOTOS` ใน `cups.js`

ข้อกำหนดรูป: สัดส่วน 1:1 · พื้นหลังโปร่ง · ปากแก้วอยู่ราว 30% จากขอบบน
เพื่อให้ขนาดและเส้นฐานของทุกแก้วดูเสมอกัน แต่ยังคงความหลากหลายของแก้วจริงไว้

## ความคืบหน้าและการเก็บข้อมูล

เก็บในเครื่องผู้ใช้ (`localStorage` คีย์ `tbc.progress.v1`) ไม่ต้องสมัครบัญชี
ไม่ต้องมีเซิร์ฟเวอร์ และไม่บังคับให้ล็อกอินก่อนได้สัมผัสผลิตภัณฑ์

```
UserBookProgress     books[CODE] = { startedAt, completedAt, firstCompletedAt,
                                     lastOpenedAt, currentChapter, chapters }
UserChapterProgress  books[CODE].chapters["18"] = "2026-08-16T…"
```

* **เปอร์เซ็นต์ไม่ถูกเก็บ** — คำนวณจากบทที่อ่านจบเสมอ
* **เล่มจบเมื่อ** `บทที่อ่านจบ === chapterCount` เท่านั้น ไม่ต้องกดยืนยันซ้ำ
* **เปิดบท ≠ อ่านจบ** ผู้ใช้ต้องกด "อ่านบทนี้จบแล้ว" เอง และยกเลิกได้ทุกเมื่อ
* มี `version` + `MIGRATIONS` — อัปเดตในอนาคตต้องไม่ทำลายข้อมูลเดิม
* ถ้าบันทึกไม่สำเร็จ จะไม่บอกผู้ใช้ว่าบันทึกแล้ว

`ProgressRepository` แยก UI ออกจากที่เก็บข้อมูล เปลี่ยนไปใช้บัญชีสมาชิก
และซิงก์ข้ามเครื่องภายหลังได้โดยไม่ต้องเขียน UI ใหม่ — เพียงเปลี่ยน adapter

## หลักการที่โค้ดนี้ยึดไว้

* ไม่มีการแต่งเนื้อหาพระคัมภีร์หรือบทเรียนขึ้นเอง
* ไม่มีลีดเดอร์บอร์ด ไม่มีการแข่งขันความเชื่อ ไม่มีการกดดันด้วย streak
* ความต่อเนื่องเป็นกำลังใจ ไม่ใช่คำตัดสิน — ขาดไปก็เดินทางต่อได้เลย
* สถานะทุกอย่างสื่อสารด้วยข้อความ/ไอคอนด้วย ไม่ใช่แค่การหมุนหรือสี
* รองรับ `prefers-reduced-motion` · โฟกัสชัด · แตะได้สบายนิ้ว (≥44px)
